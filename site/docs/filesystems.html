DEVELOPMENT DOCUMENTATION / FILESYSTEMS

Confined files, shared across agent frameworks.

A shared TypeScript client speaks 9P2000.L over an authenticated consumer WebSocket to a scoped filesystem export.

These are export subpaths in the source package, not four independently published npm packages. The rebrand does not rename these identifiers. Use the checkout's package metadata rather than assuming a public registry release.

Provision and connect

Use examples/m6-catalog-fs.toml through the fresh-catalog workflow. Declare the export's actual case behavior using fs_case_sensitivity and grant fs:connect plus the permitted file operations. Local export capabilities can narrow access further.

A GET to /v1/devices/{device_id}/services/{service_id}/fs returns the descriptor; a WebSocket upgrade with subprotocol agent-tunnel.9p.v1 opens a 9P2000.L session. The token needs fs:connect. The binary bundle includes no filesystem consumer client; the TypeScript client is a separate source integration. The provisioning regression gate reads a generated file, not every adapter's full workflow.

Ownership and authorization

The application owns the connection. Adapters borrow it and must not change its token, endpoint, root or grant. Closing one adapter must not close another adapter's handles. Cross-user connection sharing is prohibited.

Semantic boundaries

  • Paths are virtual and constrained to the exported root.
  • Write permission comes from server grants and local policy, not an SDK option.
  • Symlink and no-follow behavior must be enforced by the provider; a string-only path check is not enough.
  • Transport replay cannot establish whether a mutation completed.
  • SDK-native retries must not turn an unknown write outcome into a duplicate write.

Integration caveats

Files SDK needs its own matching FilesError class instance so failures keep their intended retry semantics. The pinned just-bash API includes synchronous metadata helpers that cannot perform asynchronous remote enumeration. Consult the source adapter contract before assuming complete filesystem equivalence.

Host support

Filesystem exports require a Unix device host, such as Linux or macOS. On Windows, tunnel-client config check and connect refuse an fs export with filesystem exports are unsupported on this host. Enrolling a Windows device or building a Windows binary does not enable filesystem exports.

Linux now uses the bounded per-component resolver when symlinks are enabled, enforcing the provider's 32-hop and per-target bounds. With symlinks disabled it uses openat2 where available, with a per-component fallback. This implementation change is not a blanket platform or adapter certification.

Verification scope

Four native adapters have compilation/contract evidence. The shared TypeScript client and one adapter have real relay/device socket evidence. Upstream records include Linux resolver tests and corrections after their first hosted run; full Linux race/deletion evidence, second-host acceptance and all-adapter end-to-end coverage remain separate. No host or adapter tests were rerun for this website review.
