Client exit codes

The implemented tunnel-client mapping distinguishes operator actions. Read the diagnostic alongside the process status.

ExitMeaningOperator action
0Success or orderly stopNo action required.
1Unexpected protocol, supervisor or signal failureInvestigate a defect or version mismatch.
2Invalid invocation or configurationCorrect the command or profile.
3Credential failure or stale authorizationRun local doctor and have the operator restore identity or authorization.
4Transport failure or closed sessionCheck reachability and session state before reconnecting.
5Deadline exceededCheck latency and the configured bounded deadline.
7OWNER_BUSY or RESOURCE_EXHAUSTED; refused before dispatchStop the conflicting connector or wait for capacity. No session work started.
130Cancellation before orderly completionInspect interruption state; an orderly Ctrl-C stop returns 0 instead.
Exit 6 is reserved for unknown outcomes but has no producer in the current client. Do not rely on receiving it to detect every ambiguous effect. Client exit 130 also covers a second stop request and a drain timeout. The relay does not otherwise use this table: it returns 0 or 1, plus 130 for an interrupted serve or an abandoned writing command. Local doctor independently returns 0, 2 or 3.

Configuration rejected

Use client config check or relay check-serve-config, not the legacy bootstrap schema checker. Check unknown fields, endpoint scheme, namespace characters and rotation timing. A dry run does not verify referenced files.

Certificate or connection failure

Run local doctor. Check the device key/certificate pairing, expiry and CA trust; verify the relay hostname and mTLS listener. Do not bypass validation or swap in test credentials.

Operational surfaces

No metrics endpoint, audit log, client status command or network doctor is supplied in this alpha. Relay logs go to stderr; retention and rotation are external responsibilities. Treat logs as sensitive: connect --json lifecycle events include local socket addresses and deadlines, even though they carry no payloads or credentials.

Use /readyz for routing new public work and /livez only for process liveness. Neither proves an end-to-end capability works. Redis backup uses the operator's tooling; recovery requires an external signing authority that is not shipped. Preserve relay membership and recovery fence state across restarts; do not reset it or restore older copies.

Connected but access denied

Check the authenticated principal's tenant membership and device/service/operation grant, local export configuration and policy revision. Some inaccessible resources deliberately appear as not found rather than leaking their existence.

Interrupted operation

Distinguish not-dispatched from unknown outcome. Reconcile the application state before retrying writes, clicks or prompts. Do not treat a transport acknowledgement or HTTP 202 as completion.

Reporting a problem

Capture the source revision, platform, selected profile, redacted identifiers, phase and counters. Exclude tokens, private keys, tool payloads, screenshots of private data and user file contents.
